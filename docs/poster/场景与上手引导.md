## 一句话定位

**把麦当劳的营养表，变成读屏软件能完整念通的一段话。**

不是「推荐吃什么」的又一个复制粘贴工具，而是**输出层**——
所有筛选、单位换算、金额读法都由脚本完成，确保读屏软件不会把
「19.88元」念成「十九点八八元」，也不会把缺失值当成0。

## 三个真实场景

### 场景 1｜视障用户，想独自完成一次点餐

**时刻**：下班回家路上，想给自己点一份，不想麻烦同事或家人代劳。

**卡在哪**
- App里的菜单是一张张图片，读屏软件念不出内容
- 不知道哪几家店还开着（营业状态、距离）
- 看不到哪些餐品自己能吃

**怎么用**：读屏模式跑一条命令，先列出门店（营业状态 + 距离），
再逐项念出能量、钠含量和能不能吃。

```bash
./scripts/mcd-a11y plan --city 北京 --keyword "望京" --profile sodium --mode screen-reader
```

**关键洞察**：读屏用户的日常本来就在键盘和文本里，**纯文本输出比图片菜单更友好**。
复制一条命令按回车，全程不需要鼠标、不需要看屏幕。
这与「换成命令行就能解决无障碍」的常见想象恰好相反：
命令行不依赖视觉定位，对读屏用户往往更友好。

---

### 场景 2｜高血压 / 糖尿病患者，每天要控钠控糖

**时刻**：医生说要限钠，但麦当劳的菜单页面上根本不标营养成分。

**卡在哪**
- 只能凭名字和图片猜钠含量高不高
- **实测15 款含「堡」的餐品，只有 2 款钠含量低于 WHO 单餐参考值**
  （汉堡包 492mg、儿童鱼排堡 442mg，其余 13 款为 673～1373mg）

**怎么用**：选定档位，按钠从低到高排序，明确念出每项是否高于本餐参考值、
超出多少毫克。

```bash
./scripts/mcd-a11y plan --city 北京 --keyword "望京" --profile sodium --mode screen-reader
```

**为什么这件事值得单独做**：能量相近的两餐，钠含量可以差 5.2 倍
（实测能量 380–560 千卡区间22 项，钠从 258mg 到 1343mg）。
「热量差不多」不等于「钠差不多」，这是菜单图片传达不了的信息。

---

### 场景 3｜子女想替父母点一份

**时刻**：爸妈上了年纪，看不清手机小字，也记不清自己想吃什么。

**卡在哪**
- 把字号调大也没用——一屏还是几十个选项，长辈选不出来
- 反过来替他们点，又不知道哪些适合长辈的身体情况

**怎么用**：大字模式一次只给 3 个选项，条目之间留空行，
不出现表格和符号。你念一句，或直接把手机递过去，都行。

```bash
./scripts/mcd-a11y demo --mode large-print --profile sodium
```

**设计要点**：大字模式不是「把字号调大」，而是**减少同时呈现的信息量**。
对认知负担高的用户，少给几个选项比放大几个选项更有用。

## 怎么体验：三条命令

### 第1 步 · 先看效果（不需要任何凭据）

```bash
git clone https://github.com/Lion-bot2026/mcd-a11y-order.git
cd mcd-a11y-order
./scripts/mcd-a11y demo --mode screen-reader --profile sodium
```

营养数据是官方 MCP 真实返回的 160 条快照，门店是合成样例。
想试其他档位：`--profile carb --meal-kcal 600`。

### 第 2 步 · 切成大字版看看

```bash
./scripts/mcd-a11y demo --mode large-print --profile sodium
```

### 第 3 步 · 查你附近的真实门店（这一步才需要 Token）

```bash
export MCD_MCP_TOKEN=你的Token        # 从 https://open.mcd.cn/mcp 申请
./scripts/mcd-a11y plan --city 北京 --keyword "望京" --profile sodium
```

也可以先跑 `./scripts/mcd-a11y profiles` 看四个档位的阈值出处和核实状态——
本项目把「哪些数字有权威口径、哪些是工程假设」直接标出来，不含糊过去。

## 三种输出模式怎么选

| 模式 | 给谁用 | 输出特点 |
|---|---|---|
| `screen-reader` | 视障用户（NVDA / VoiceOver） | 中文货币读法、无表格、无符号、单位全中文、显式播报进度、编号连写 |
| `large-print` | 长辈、认知障碍者 | 一次 3 项、条目留白、信息收敛 |
| `plain` | 视力正常的开发者 / 自己看 | 普通 Markdown，条目完整 |

---

## 它不做什么（这部分同样要讲清楚）

- **不自动下单、不代付。** 下单必须手动加 `--confirm` 二次确认。
- **不提供门店无障碍设施信息。** 麦当劳 MCP 不返回坡道、无障碍卫生间、
  低位柜台等数据，工具无法核实，请到店前致电门店确认。
- **不量化特制后的钠含量。** 官方特制接口不返回分项营养数据，
  所以只给方向性提示，不编造「去酱能减多少毫克」。
- **不提供低蛋白档位。** 慢性肾脏病的蛋白质摄入需按体重与分期个体化确定，
  给固定克数会有误导风险。
- **不是医疗或营养建议。** 只陈述「某个数值与某个参考值的高低关系」，
  不对产品本身作评价。

## 海报数字溯源

海报上每个数字都来自 `data/nutrition_snapshot.json`（官方 MCP 实时返回），
可用项目代码复算：

| 海报数字 | 复算方式 |
|---|---|
| 160 条 | `len(demo_data.load_nutrition())` |
| 2 / 15 款汉堡低于参考值 | 按品名含「堡」筛选，对比 667mg |
| 5.2 倍 | 能量 380–560 千卡区间钠含量 max/min |

复核命令：

```bash
python3 -c "
import sys; sys.path.insert(0,'.')
from mcd_a11y import demo_data
f=demo_data.load_nutrition()
b=[x for x in f if '堡' in x.product_name]
low=[x for x in b if x.sodium_mg<667]
print(f'堡类{len(b)}款, 低于667mg的{len(low)}款')
band=[x.sodium_mg for x in f if x.energy_kcal and 380<=x.energy_kcal<=560]
print(f'能量380-560: {min(band)}-{max(band)}mg, 跨度{max(band)/min(band):.1f}倍')
"
```
